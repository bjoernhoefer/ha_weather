What can I do here?

  • Foldable sections: click a section title to open or close it. Only Forecast → Next 24 hours is open by default.
  • Location and forecast: select a location to see the weighted consensus forecast for the next 24 hours, the next 48 hours (four-hour intervals) and days 3–7. Reload uses the cached result; Refresh forecast queries the sources again.
  • History, last 24 hours: compares what was predicted for each past hour with the measured value (Home Assistant outdoor sensors, otherwise Open-Meteo) and shows the mean absolute error and bias.
  • Providers (Top / Low): compare weather sources by measured accuracy. Explain shows each provider's archived forecasts against outdoor measurements over the past 30 days and the errors behind its score. A manual rank or disabled provider overrides the automatic order; Reset removes that override.
  • Source control: enable or disable sources for all locations, save API keys for sources that need them, or add a keyless Open-Meteo model.
  • Seasons and garden indicators: view seasonal and upcoming weather changes alongside evapotranspiration, water balance, sunshine, radiation and soil moisture.
  • Real world measurements: add any number of Home Assistant instances (URL + long-lived token), then add measurements that couple a sensor entity of an instance with a location and indoor/outdoor scope. Edit or delete them in the list. Elasticsearch works the same way: add any number of instances (URL, API key, index, location field), then add fields that couple a temperature field of an instance with a location and scope. Deleting an instance also deletes its measurements or fields.
  • General settings: add a location by name (optionally with latitude/longitude for better accuracy) or delete locations added here, and enter the API key.
  • Logging: below General settings, open the panel to inspect recent updates, configuration changes and safe failure summaries. Refresh logs or change the minimum severity to fetch the latest entries.
  • Verify with Azure AI Foundry: request an additional assessment when an Azure AI Foundry deployment is configured.
  • Public mode: enter your API key under General settings; it opens automatically when the key is missing or wrong. The key is stored in this browser.

Logging / Protokoll

The Logging panel loads on opening, on severity changes and with Refresh logs; it does not poll in the background. It also reports failed optional garden/soil updates and Azure verification. INFO shows all entries, WARNING includes warnings and errors, and ERROR shows only errors. Timestamps are UTC. Up to 100 matching entries appear newest first.

The service keeps its latest 500 entries in memory per process. Restart clears the history; workers have separate logs. This is not a durable audit trail. Log reads and cached forecast reads do not create updates. Access is anonymous in local mode and uses your API key in public mode. Messages show safe summaries and recognized error categories, not credentials, entered settings or raw exception details; use server/container logs for further investigation.

Der Abschnitt Logging unter General settings lädt beim Öffnen, beim Wechsel der Mindeststufe und mit Refresh logs; es gibt keine automatische Abfrage im Hintergrund. Er zeigt auch fehlgeschlagene optionale Garten-/Bodenaktualisierungen und Azure-Prüfungen. INFO zeigt alle Einträge, WARNING Warnungen und Fehler, ERROR nur Fehler. Zeitangaben sind UTC. Höchstens 100 passende Einträge werden angezeigt, die neuesten zuerst.

Die letzten 500 Einträge bleiben je Dienstprozess im Arbeitsspeicher. Ein Neustart löscht sie; Worker haben getrennte Protokolle. Dies ist kein dauerhaftes Auditprotokoll. Protokollabfragen und Wetterabfragen aus dem Cache erzeugen keine Aktualisierungseinträge. Lokal ist der Zugriff anonym, im öffentlichen Modus wird der vorhandene API-Schlüssel benötigt. Meldungen enthalten sichere Zusammenfassungen und bekannte Fehlerkategorien, keine Zugangsdaten, eingegebenen Einstellungen oder vollständigen Ausnahmen; Details stehen in den Server-/Containerlogs.
